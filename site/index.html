Send the address,
not the data.

Most systems spend their lives copying the same data between programs — serialize, send, receive, parse, repeat. Holon takes a different deal: programs on one machine share their data in memory, and a message just says where to look. The result is requests answered in about a microsecond, workers you can kill mid-job without losing a single message, and data tables every worker reads at full speed without ever holding a copy.

Every message is exactly 64 bytes — the size of one CPU cache line. The data never travels; the message carries its address. hover a field ↓
The interesting fields: payload says where the data lives in shared memory, and version says exactly which edition of it this message is about — so a worker never reads newer data than the sender meant.
Why this exists

Three problems every fast system hits

Copying is an invisible tax

Services that talk over sockets or queues serialize and copy the same bytes all day — often more CPU than the actual work. Here, data is written to shared memory once; every message after that is a 24-byte note saying where it is.

Restarts lose everything a service knew

When state lives inside a service, restarting it means warm-up, replay, or an outage. Here, state lives in shared, versioned tables outside the workers — so restarting a worker loses nothing, because it owned nothing.

Crashes lose work in flight

Most systems hope their retry logic covers a crash. Here recovery is mechanical and measured: kill a worker mid-job and a replacement answers about half a second later, the job re-delivered, nothing lost, no memory leaked — proven on this page, below.

If you're building trading systems, market-data fan-out, pricing grids, real-time analytics — anything where many processes on one machine hammer the same data — this is the shape built for you. The rest of this page shows how it works and proves the claims; the deep technical story lives in the guide.

The framework

Small workers, shared memory, no sharing of blame

You write actors: small handlers that receive one message at a time, so you never write a lock. Data they read is pinned for exactly as long as they read it — the framework guarantees nobody frees or changes it under them. Under the hood: messages ride a lock-free queue, dispatch is a function-pointer table, and nothing allocates on the message path. One process can host many actors; several processes with the same name form a pool that covers for each other.

// host side: any number of actors, one mailbox, routed by `to`
let mut sys = ActorSystem::attach(&node)?;
sys.spawn("pricer", Pricer::new(curve_ref))?;
sys.spawn("risk",   Risk::new(curve_ref))?;
sys.run()?;

// a handler pins the exact cell version its message names
impl Actor for Pricer {
    fn handle(&mut self, cx: &Cx, env: &Envelope, req: PriceRequest) -> Reply {
        let curve = cx.pin(&self.curve)?;   // journaled: kill -9 safe
        price(curve.as_arrow(), req.tenor)     // zero-copy view
    }
}

// client side
let pricer = client.actor_ref::<PriceRequest>("pricer")?;
let reply  = pricer.ask(&req, timeout)?;        // or .tell(&evt)
  • State lives in shared tables, not inside workers. A price curve, an order book, a stream of ticks — each is a versioned table (stored in Apache Arrow format, so analytics tools read it natively). Any worker can read any version, at full speed, without a copy.
  • Asking a question is safe even if the answerer dies. The asker sets aside the memory for its own answer before asking — so a half-dead worker can never scribble on someone else's reply. This rule came out of crash testing, not a whiteboard.
  • Failover is visible if you care, invisible if you don't. Every reply says which incarnation of the worker produced it and whether the job was retried. Most callers never look; the ones that must, can.

The substrate: shm-actors

  
One copy in. Zero copies after.

  
Underneath the framework sits shm-actors, the memory engine. Think of it as
  a warehouse every worker can see into: data is put on a shelf once, and from then on everyone
  passes around shelf labels — 24-byte notes that are cheap to send and impossible to
  confuse with a stale shelf, because every label is checked before use. A small
  coordinator process hands out keys to the warehouse and cleans up after
  crashes; it never touches the data itself, so even if it dies, everyone keeps working.


  

    
shm-ring Broadcast
One publisher, many listeners, 83½ billionths of a second per hop — announcing to another process costs the same as to another CPU core.
How it works →

    
shm-task Job queue
Workers claim jobs in constant time however big the queue is. Every job has a lease: if its worker dies, the job is handed to someone else — with a counter, so nothing is ever done twice unknowingly.
How it works →

    
shm-artifact Versioned tables
Data tables with editions. Readers grab an edition instantly and keep it frozen while writers publish the next; growing a table costs the same whether it holds ten rows of history or a hundred thousand.
How it works →

    
shm-stream All-or-nothing writes
Build up a batch of changes invisibly, publish them as one edition. If the writer aborts — or dies — readers never see half of anything.
How it works →

  


  
The safety story is Rust's famous ownership rules, extended across whole programs: one
  writer at a time, readers hold what they read, and everything a crashed process was holding is
  found in its journal and returned — by replaying records, not by hoping. Tests
  count every block of memory after every crash drill; the books always balance.

Why trust it

  
Tested like an attacker, documented like an auditor

  
This project's test suite doesn't check that things work — it tries to make them fail:
  processes killed at every step, memory counted to the byte afterwards, random garbage fed to
  every parser, and the trickiest lock-free logic checked by a tool that explores every
  possible thread interleaving, not just the ones that happened to occur.

  

    
239 tests that attack
Race two writers, kill readers mid-read, replay crashes — then count every block of memory. The books must balance exactly, every time.

    
Every interleaving, checked
The four core lock-free algorithms are exhaustively model-checked (with loom) — and the checks are proven sharp by showing they fail on deliberately broken versions.

    
Garbage in, never a crash out
Every parser that reads untrusted bytes is fuzzed continuously. Malformed input gets an error, never a panic, never an out-of-bounds read.

    
Nothing changes silently
Every shared-memory format is frozen and machine-asserted, and every reference is validity-checked before use — stale data fails loudly instead of lying quietly.

  

  
Wording rules are part of the engineering: “zero-copy” is defined, the
  timer floor is named, memcpy throughput is not called ingestion, no comparison baseline exists so
  no “N× faster than X” is claimed, and a bench that can't distinguish two designs is replaced
  rather than quoted.
