The guide

Bottom-up: the shm-actors substrate first — the memory model, then each primitive built on it — and the Holon actor framework on top. Every section names the crate that implements it and the ADR that decided it.

shm-core · ADR-0001

The memory model

Everything lives in segments (shm_open + mmap) carved into fixed size-class pools. Allocation rounds a request up to the first class that fits; free lists are lock-free Treiber stacks with tagged heads, so external fragmentation is structurally impossible and ABA is designed out.

The chunk control word

Every chunk carries a ChunkCtrl: state, owner, refcount and a generation counter, packed so state and refcount move in one atomic word.

FREEon the free-list
try_loan ▶writer owns it
LOANEDwritten exactly once
publish ▶one CAS
PUBLISHEDrefcounted, immutable
refcount → 0 ▶generation bumps
FREErecycled
  • Loans are exclusive. A writer serializes a payload into loaned chunks; nothing can observe them until publish.
  • Published chunks are immutable. Readers take shared references (borrow_shared fails the instant a chunk is not PUBLISHED — there is no window where a count lands on a dying chunk).
  • Generations make staleness detectable. A 24-byte ChunkDesc records the generation it was written at; any dereference validates it. A recycled chunk fails the check instead of leaking someone else's data.

The borrow journal

Each actor owns a fixed-slot journal in shared memory. Every cross-process borrow — a staged chunk, a version pin, a write lease — records a slot; a clean release clears it. When an actor dies, the coordinator's lease monitor replays the journal: staged chunks are freed, pins decremented, leases force-released and fenced so a zombie that wakes up later can never install anything. Crash safety is replay, not heuristics.

shm-arrow

Arrow as the payload format

A RecordBatch is serialized once into chunks in Arrow's own buffer layout, with schemas interned to a u32. Reconstruction builds column buffers that point directly into the mapped segment — a clone of the pin is the buffers' keep-alive, so a batch can outlive the call that produced it but never the version it views.

  • Reconstruct cost is flat vs. row count: 208–250 ns whether the table holds 1 000 or 1 000 000 rows.
  • A large or nested batch spans several chunks (spans are recorded per batch); it round-trips intact.
  • Write throughput (~80 GB/s on the dev machine) is memcpy throughput for this workload — the docs refuse to call it “ingestion”.
shm-ring

Pub/sub: the broadcast ring

A single-producer, multi-consumer ring of fixed slots with per-subscriber cursors. Producers never wait on consumers; a slow subscriber observes loss explicitly rather than exerting backpressure on the bus. Messages are descriptors, so fan-out costs the same whether the payload is 100 bytes or 100 MB. One-way hop: 83.5 ns p50 cross-process — the same as cross-core, because it is the same cache-coherency traffic.

shm-artifact · ADR-0013 / 0016

Versioned cells

An artifact is a named, versioned Arrow table. One RCU head holds current; commits install with a single linearising CAS; readers pin:

// reader: pin whatever is current, get a zero-copy view
let pin  = artifact.pin()?;                 // ≤ 1 tick, any history depth
let view = pin.as_arrow_batches(®istry)?; // buffers point into shm

// writer: exclusive (leased) or optimistic (CAS race)
let mut w = artifact.open_exclusive_journaled(me, &journal)?;
w.commit(Commit::Append, &batch, ®istry)?;   // O(new data)

Chained manifests

Each version's manifest lists only its own chunks plus one refcounted link to its predecessor — so the table is the chain, and Append costs O(new data) no matter how long the lineage grows (measured flat past 100 000 versions). Retirement is a cascade that runs exactly once per manifest, elected by CAS; a pinned old version keeps exactly its own chain alive and nothing more.

Windowed append + delta read

High-churn cells stay bounded with three pieces (ADR-0016):

// producer: append, re-rooting on the newest K batches every K commits
let policy = WindowPolicy::new(256);
entry.append_windowed(&policy, &tick_batch)?;   // zero bytes copied, ever

// consumer: pay only for what's new
let (pin, delta) = entry.read_since(last_seen)?;
for batch in &delta.batches { apply(batch); }   // ~290 ns, flat
if delta.truncated { resync(&delta.batches); }   // a Replace happened
last_seen = pin.version();

Commit::Window builds a fresh root that re-lists the newest K batches by reference; the tail of history cascades back to the pool. The root records which version every kept batch came from, so a window is invisible to any reader that keeps up — it receives exactly the rows it lacks. A Replace is never silently papered over: delta.truncated tells the reader its history is gone. Live memory, manifest size and read cost are all bounded by the policy, forever.

shm-task · ADR-0009 / 0012

Tasks

An MPMC queue whose messages are descriptors. Submit and claim are O(1) via FREE/READY index stacks — measured identical at capacity 256 and 65 536. A claimed task carries a lease; a worker that dies past its lease has the task redelivered, and the slot records the attempt count so consumers can act on redelivery exactly.

The contention story is a case study in method (ADR-0012): aggregate throughput fell with workers until per-worker counters isolated the defect — a handle clone costing two atomic refcount RMWs per claim. Layout theories (padding, sharding) were tried first and changed nothing. Counters, not theory: 4.5 M/s negative-scaling became a flat 5–9 M/s.

shm-stream · ADR-0002

Transactional streams

let mut tx = StreamWriter::open(&artifact, &seg, &journal, ®, me,
                              Commit::Append, Coordination::Exclusive)?;
tx.append_batch(&a)?;   // staged: LOANED, journaled, invisible
tx.append_batch(&b)?;
tx.commit()?;            // one CAS: readers see v(n) then v(n+1)

Isolation because staged chunks are loaned and named by no manifest; atomicity because the install is the artifact's single CAS; abort (or Drop, or death) frees every staged chunk with nothing published. A writer crash mid-transaction is unwound by journal replay — the stream needs no extra crash machinery.

shm-store · ADR-0007 / 0008

The keyed store

Names over artifacts: a catalog maps byte keys to entries, each entry owning an artifact, typed refs, and lifecycle. Slots reclaim under churn (create/evict far past capacity runs indefinitely); a reclaimed slot gets a new incarnation, so stale handles fail cleanly instead of resolving to a stranger. evict_current drops the data but keeps the address — what a task-output cache wants for ack-and-clear.

shm-runtime · ADR-0003 / 0010 / 0014

The runtime

The coordinator hosts the registry and passes segment fds over a Unix socket (SCM_RIGHTS). Actors register, receive their segments and journal, and never make another control-plane call on the hot path. The lease monitor watches actor liveness: on death it fences the actor's write leases and replays its journal. Doorbells are the platform seam — one-byte UDS writes on the POSIX baseline, futex/eventfd on Linux — chosen because the substrate costs 83.5 ns while a parked wake costs ~4.4 µs: the wake, not the memory model, is the budget.

holon-core / holon-actor · ADR-0015

The Holon actor framework

Actors own no state; memory nodes own no code. An actor is a message loop: envelopes ride the task queue, payloads live in versioned cells, and the handler pins the exact cell version its message named. Dispatch is a sorted table of function pointers — no dyn, no allocation on the message path.

let mut sys = ActorSystem::attach(&node)?;
sys.spawn("pricer", Pricer::new(curve_ref))?;   // any number of actors,
sys.spawn("risk",   Risk::new(curve_ref))?;     // one mailbox, routed by `to`
sys.run()?;

// client side
let pricer = client.actor_ref::<PriceRequest>("pricer")?;
let reply  = pricer.ask(&req, timeout)?;        // or .tell(&evt)
  • One 64-byte envelope — one cache line, frozen ABI — is both the mailbox slot and, by design, the future TCP frame header. Small bodies ride inline; anything else is a packed reference into the shared pool.
  • The asker allocates the reply chunk and names it in the request. This came out of the demo, not the whiteboard: the task slot's result word is reused by the free-list before the asker can poll it under concurrency, so the reply must live in memory the asker owns. Handlers time-fence their reply write at half the lease, so a lease-lapsed zombie never writes into freed memory.
  • N processes of the same name form a pool; redelivery + incarnation-tagged replies make failover observable to the client that cares and invisible to the one that doesn't.

Measured: ask round trip 9.5 µs p50 parked / 1.2 µs spinning; 168–186 K asks/s at 4 clients × 4 pricers; the envelope layer itself accounts for ~2 µs parked, ~0.7 µs spinning — the rest is the doorbell. Crash-to-successor is the lease plus one tick: 522–543 ms at a 500 ms lease, with one redelivery, zero losses and an exact pool census after.

Platform · ADR-0011

Platform & roadmap honesty

  • Baseline (measured): portable POSIX — shm_open + mmap, UDS doorbells, coordinator leases for death detection. Dev on macOS.
  • Linux fast paths (built, unmeasured): futex doorbells, memfd sealing behind the platform seam. They compile clean under -D warnings cross-target; no futex numbers are quoted because none have been measured.
  • Not yet: cross-host transport (the envelope is designed as the frame header, but no network face ships), Commit::Patch, per-actor mailboxes (head-of-line isolation between co-hosted actors).
