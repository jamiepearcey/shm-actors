# ADR-0002 — v0.2 scope, sequence, and walking skeleton

- Status: Accepted
- Date: 2026-07-22
- Decider: architecture (Fable 5), transcribed by implementation
- Builds on: [ADR-0001](ADR-0001-foundation-and-scope.md)

## Context

v0.1 is delivered and green (5 crates, walking skeleton proves
publish→pin→`kill -9`→lease/journal-replay→reclaim). The deferred set spans nine
candidates (A–I). This ADR fixes what v0.2 delivers.

## Decision

### Scope

**IN v0.2: A, B, C, D. OUT (v0.3+): E, F, G, H, I.**

Cut line: v0.2 must make a cache-shaped application *buildable* — complete the
primitive set (task, stream), make commit observable (A), and make waiting free
(D). E (cross-process schema coordinator), F (multi-chunk/nested Arrow), H
(Linux fast paths), I (Patch commits / live-version cap) are capacity,
portability, and richness polish; G (journal-segment consolidation) is internal
hygiene. None block application shape.

- **A** — wire `shm-artifact` `VersionEvent`→ring on `__artifacts` in
  `shm-runtime` (watch-on-commit).
- **B** — `shm-task`: MPMC task queue, workers claim by CAS on slot state
  (QUEUED→CLAIMED→DONE), correlation id = slot seq, crash resets CLAIMED→QUEUED
  (at-least-once), cancel/timeout via per-task flag. The 3rd primitive.
- **C** — `shm-stream`: ordered chunked sequence with transactional commit atop
  `shm-artifact`; `append_batch` stages invisible chunks, `commit()` installs a
  new artifact version, abort/crash frees staged. The 4th primitive.
- **D** — real doorbell wakeup: `Notifier`/`Parker` backed by `Platform`,
  replacing spin/yield, so idle subscribers/workers don't burn CPU.

### Sequence (one agent per stage, sequential — no concurrent cargo)

1. **D** — doorbell wakeup. First: it is the only frozen-ABI touch (get risk out
   early), and B's workers / A's watchers park on it.
2. **B** — `shm-task` (largest; dedicated agent).
3. **C** — `shm-stream` atop `shm-artifact`.
4. **A + skeleton** — VersionEvent→ring wiring folded into the v0.2 walking
   skeleton + integration test (Fable permitted folding A here).

B and C both consume D's Parker API, so D lands first.

### v0.2 walking skeleton — "the cache loop"

Producer stages batches into a **stream**, `commit()` installs an artifact
version → **VersionEvent** on `__artifacts` → a **watcher** (parked on the
doorbell; assert ~0% CPU while idle) wakes and enqueues a **task** → **worker**
CAS-claims, pins the version zero-copy, marks DONE. Then two kills:
(a) `kill -9` worker mid-CLAIMED → lease resets CLAIMED→QUEUED, a second worker
completes (at-least-once observed via correlation id); (b) `kill -9` producer
mid-stage → journal replay frees staged chunks, no version ever published.

### ABI rulings (binding)

- **`shm-task` gets its OWN slot ABI.** Do not reuse/extend `shm-ring`'s `Slot`:
  broadcast SPMC is wait-free/no-CAS; MPMC claim is a CAS state machine with
  owner+deadline — sharing would poison the ring invariant.
  `TaskSlot{state, owner, seq, deadline, payload: ChunkDesc}` fixed-size;
  payload lives in pool chunks; correlation id = slot seq.
- **D touches the ring header minimally.** The v0.1 ring header already carries
  an `AtomicU32 waiters` hint and the `Notifier`/`Parker` seam; D provides a real
  `Platform`-backed doorbell impl and does not add new on-shm fields. Waiter
  *registration*/doorbell-fd distribution is control-plane (coordinator
  UDS/`SCM_RIGHTS`), not on-shm. Bump the ring format const if any header bit
  changes; shm regions are process-lifetime, never persisted, so no migration.
- **E (deferred) changes nothing now.** `ChunkDesc.schema_id` stays
  registry-scoped with deterministic seeding; the v0.3 coordinator-interning
  design keeps the field as-is.
- **A freezes `VersionEvent` as a fixed-size `SharedPod`**
  `{artifact_id, version, manifest: PackedRef, kind}` — no varlen payload on the
  ring.
- **C adds no `ChunkCtrl` state.** Staged chunks are LOANED + journal-recorded
  (crash replay already frees them); `commit()` = artifact `Append`. Stream
  metadata is an additive `StreamHead` chunk.

### Risk classification

- **Pure additive (v0.1 stays green):** A, B, C.
- **Touches frozen ABI:** D only — land first; the full `shm-ring` test suite
  must pass before stage 2 begins.
